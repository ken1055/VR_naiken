Get Japan eSIM — 訪日旅行者向け eSIM 販売サイト

期間 2026.03 〜 2026.06規模 204 コミット・約 8,100 行体制 単独

海外からの旅行者が日本到着前にデータ通信プランを購入し、メールで届く QR コードで即日開通できる EC サイト。 プラン比較から決済、購入後のマイページまでを一貫して設計・実装しました。

  • 商品と決済: 全国・多国間の 2 カテゴリ × 3 プラン。Stripe Checkout で決済し、Webhook で購入確定を受信。署名検証と完了画面での決済再確認で、URL 直打ちによるなりすましを防止
  • 多言語・多通貨: 英語・ドイツ語・中国語の 3 言語、USD / EUR の 2 通貨を切替。100 箇所以上の文言を辞書管理
  • 購入後体験: メール認証付きの「My eSIMs」ポータルで QR を再発行。利用規約・返金・プライバシー・法的表記ページを整備
  • 運用コスト設計: Composer や SDK に依存しない PHP で Stripe API を直接呼び出し、月額数百円のレンタルサーバーでも動作。鍵未設定時はモック決済で先行開発できる仕組み
  • 品質: スマホ表示の崩れを 1 件ずつ潰し込み、Playwright で画面確認。コミット履歴に改善の経緯を残す運用

FC 店舗管理システム — 売上・顧客・ロイヤリティ・請求書を一元管理

期間 2025.07 〜 2025.10規模 320 コミット・約 12,000 行体制 単独

フランチャイズ本部が加盟店舗の売上と顧客を一元管理し、毎月のロイヤリティ計算と請求書発行を自動化する Web システム。 紙と Excel で行っていた月次業務を、店舗側の入力から本部側の請求までオンラインで完結させました。

  • 店舗・売上・顧客: 店舗プロフィール、月次売上入力、売上履歴のフィルタ、顧客台帳と来店取引の紐付け（売上と顧客の連携設計書を作成）
  • ロイヤリティ自動計算: 店舗ごとに料率と適用開始日を設定し、月次売上から自動算出。月末日の境界バグなど実運用で見つかった問題も修正
  • 請求書 PDF: 日本語フォントを埋め込んだ PDF を生成し、一括発行・閲覧・ダウンロード。月次・年次の売上とロイヤリティのレポート画面
  • 基盤と移行: SQLite で素早く立ち上げ、本番は Vercel + Supabase（PostgreSQL、行レベルセキュリティ）へ全ルートを移行。セッション永続化やレンタルサーバーの MySQL への移行手順も整備
  • 引き継ぎ: デプロイ・環境変数・DB エクスポート・セッション改善など 16 本の運用ドキュメントを同梱

Truss — 国際交流サークルの会員管理・イベント運営アプリ

期間 2025.09 〜 2026.03（2 世代）規模 119 コミット・約 43,000 行体制 単独（デザインは Figma を起点）

大学の国際交流サークル向けに、会員登録から承認・会費・イベント参加・掲示板までを 1 つにまとめた会員アプリ。 第 1 世代（Next.js）で言語・時間帯・性別比を考慮したグループマッチングを実装し、第 2 世代では Figma デザインを起点に PWA として全面刷新しました。

  • 会員ライフサイクル: メール認証 → 初期登録 → 承認待ち → 限定アクセス → プロフィール完成 → 会費支払い → 正会員、の 9 段階を状態として管理。学生証の再提出依頼、年度更新と継続会員の扱いにも対応
  • 管理ダッシュボード: 入会承認、会員検索・詳細・ブロック、イベント作成と参加者管理、写真ギャラリーの承認、会員とのチャット、通知配信、一括メール
  • 会員体験: CODE128 のバーコード会員証、イベントへの参加・いいね、掲示板と返信、Realtime による即時反映、日本語 / 英語切替
  • 認証と基盤: Supabase Auth（メール + Google OAuth）、行レベルセキュリティ、ストレージ、6 本のマイグレーション。開発環境から本番 Supabase への移行ガイドを作成

VR 内見ビューア — 本物の部屋をブラウザだけで歩ける内見体験

期間 2026.06 〜 運用中規模 50 コミット・約 7,200 行体制 単独

3D Gaussian Splatting で撮影した実物件を、アプリ不要で歩き回れる Web ビューア。撮影データの前処理から配信、物件ごとの固有 URL と QR の発行、流入元別の閲覧計測まで、不動産会社がエンジニア無しで運用できる形に仕上げました。

  • 体験: 床に目線を固定したウォークモード、自動生成コリジョン、テレポート、360 度写真との連携、スマホのジョイスティック操作
  • 性能: 配信データを 59MB → 13.5MB（-77%）に圧縮し、画質差を数値で検証して採用
  • 運用基盤: Cloudflare Workers + D1 で物件レジストリ・OGP 注入・QR 生成・閲覧イベント集計。公開準備は「フォルダを選んで実行」の 1 ボタン（116 万点のデータで 43 秒）

AIMY — AI 肌診断とパーソナライズ提案

期間 2026.06規模 約 13,800 行（解析 7 種）体制 単独

スマホで撮った顔写真から、シミ・シワ・毛穴・キメ・赤みを解析して可視化し、将来の肌変化シミュレーションと化粧品・施術の提案レポートを生成する Web アプリ。 美容医療の高額な診断機器に近い見せ方をブラウザだけで実現することを狙いました。

  • 画像解析: MediaPipe の顔ランドマークで肌領域を抽出し、OpenCV と scikit-image でシミ（Hessian ブロブ検出・3 段階分類）、毛穴（モルフォロジー）、シワ、キメ、赤み、エイジングの 7 つの解析 API を実装
  • 見せ方: 業務用診断機器に近いトーンマッピング表現を独自に再現。検出マーカーを描くのではなく自然に強調する方式
  • 生成 AI: Gemini API で悩み別のレポート文と化粧品レコメンドを生成。投資家向けピッチページも同梱
  • 基盤: Flask + gunicorn でクラウドにデプロイ可能、ローカル開発サーバーも同梱

How I Work

進め方と、大切にしていること

「動くものを早く見せて、使いながら直す」を基本に、引き継げる形で納めます。

業務のヒアリング

今の業務フロー（Excel・紙・口頭）を確認し、どこを自動化すると効果が大きいかを一緒に決めます。

画面と設計の合意

画面イメージとデータ構造を先に共有。FC 管理では「売上と顧客の連携」を設計書にしてから実装しました。

短いサイクルで実装

AI 開発ツールを活用し、数日単位で動く画面をお見せします。eSIM の購入導線は 2 日で決済まで通しました。

本番公開と計測

クラウドへのデプロイ、決済・メールの本番切替、アクセス計測まで対応。障害時は原因と再発防止策を文書化します。

引き継ぎ・運用

デプロイ手順・環境変数・DB のバックアップ方法などを手順書として納品。社内でも外部でも引き継げる状態にします。

少人数でも止まらない体制

9 件すべてを一人で設計から運用まで回してきました。AI 開発ツールを本格活用することで、従来なら数名のチームが必要な規模を、短期間・低コストで形にできます。

数字で判断する

配信データの圧縮では画質差を数値で比較し、コリジョンの不具合では到達面積を測って回帰テスト化。感覚ではなく計測で決めます。

業務とお金の流れを理解する

ロイヤリティ計算、代理店の売上、会費と年度更新、越境 EC の決済と返金。システムの裏にある業務とお金の流れを理解したうえで設計します。
